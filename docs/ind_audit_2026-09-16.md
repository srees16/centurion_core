## 1. Dead code removed

Whole modules with no importer anywhere (verified by import graph, not by
name): the five unwired "institutional layer" facades, `infrastructure/
analysis_pipeline.py`, the entire `cloud/` package, two optimizer scripts, 11
`*_bktest.py` harnesses plus `trading_strategies/backtest_utils.py`, six
orphan services, `ui/pages/analysis_page.py`, three `infrastructure/` modules,
a stale pickle checkpoint, and ~900 lines of superseded
`detect_backtest_regime*` variants in `services/regime/regime_detector.py`
(the live API — `detect_regime`, `get_current_regime`, `MarketRegime`,
`RegimeSnapshot` — is intact).

Also removed: `estimate_trade_cost` (no callers) and 42 `Config` attributes no
code reads — never-wired indicator periods, the "new alpha sources" weights,
forecast gates, legacy PBO knobs, the RL block, TimescaleDB and metric
toggles, and knobs of code paths already deleted.

## 2. Duplication removed

| Was duplicated | Now |
|---|---|
| NSE browser headers + cookie-primed session in three modules, with three different User-Agent versions | `infrastructure/nse_http.py` |
| Risk-free rates in `config.py` and `services/risk/risk_metrics.py`, plus a third value in `benchmark_tracker` | `Config.RISK_FREE_RATE_IND` / `_US`, imported |
| Annualisation as `16`, `16.0` and `sqrt(252)` in three vol modules | one `ANNUALISATION_FACTOR = sqrt(252)` |
| NIFTY 50 constituents in `ui/components.py` and `kite_connect/core/config.py` | derived from `INDEX_CONSTITUENTS` |

The annualisation change is the only one that moves a number:
`volatility_target` and `portfolio_vol_monitor` were annualising with
sqrt(256), so their annualised vol was 0.8% high. The deployed NSE engine has
its own metrics module and is unaffected.

No duplicate or near-duplicate files remain (checked by content hash over
every `.py`, and by hashing every function and class body over 8 lines).

## 3. Folder structure

`services/` was 68 modules in one directory; they are now grouped by the job
they do:

```
services/
  app/           Streamlit app services: analysis runs, session state, cache
  decision_engine/  rules engine for trade decisions
  execution/     order execution, overlays, strategy runners
  market_data/   bhavcopy, delivery, corporate actions, events
  metrics/       technical indicator calculators
  notifications/ email / webhook / SMS alerts
  portfolio/     allocation, weighting, portfolio analysis
  regime/        regime detection and regime-conditional weights
  research/      backtests, statistical validation, live-vs-backtest
  risk/          volatility, position risk, stops, risk metrics
  rl_bot/        reinforcement-learning trade bot
  sentiment/     multi-source sentiment aggregation
  signals/       forecast generation and combination (Carver ±20)
  storage/       MinIO / local file storage
  technical_analysis/  RSI, MACD, Bollinger, Supertrend aggregator
```

`services/layers/` held one live module once the dead facades went, so its
monitoring service moved to `infrastructure/monitoring.py`, beside the latency
tracker and event bus it builds on.

Left alone on purpose: `nse_engine/` (the validated engine — its module paths
are pinned by the deployment and the daily Actions job), `runners/`,
`kite_connect/` (already grouped by task), `config/`, `data/`, and the
root-level entry points (`app.py`, `main.py`, `cloud_paper_runner.py`,
`setup_database.py`) that the README and workflows invoke by name.
